# ERA_ANALYSIS.md — Phase 0 Deep Analysis

**Project:** Generation Camera — an Android camera app with an "Eras Dial" spanning the **1900s → 2020s** (13 stops), a **Degree Control (0–10)** per era, and an era-matched **Frame Switch**. Inspired by the FUJIFILM instax mini Evo Cinema™ Eras Dial, extended backward to 1900/1910/1920.

> We emulate the *look* of each era with standard, published image-processing techniques (3D LUTs, procedural grain, vignette, halation, overlay textures). We make **no claim** to replicate Fujifilm's proprietary algorithms.

---

## 0.1 Effect mechanism decomposition

An "era look" is decomposed into **independently controllable layers**. Each layer states its algorithm and **where it runs** in the render pipeline. The pipeline (detailed in `ARCHITECTURE.md`) is:

```
Camera (OES texture)
  → P1: scene pass (YUV/OES → linear-ish RGB FBO, geometry: gate weave / down-res)
  → P2: blur pyramid (half-res separable Gaussian FBO ×2) — feeds soft focus, halation, unsharp
  → P3: "era" über-shader (LUT + tone + grain + vignette + halation + dust + leaks + artifacts)
  → P4: frame overlay quad (alpha-blended)
```

| # | Layer | Algorithm | Pipeline stage |
|---|-------|-----------|----------------|
| 1 | **Tone curve / contrast** | Baked into the per-era **3D LUT** (lift/gamma/gain + per-channel S-curves, faded or crushed blacks). A small runtime contrast/exposure trim uniform allows the degree model to scale contrast continuously without LUT swapping. | LUT generation (offline) + P3 |
| 2 | **Color grading** | One **`.cube` 3D LUT (17³)** per era, generated by `tools/generate_assets.py` (white balance → channel mixer/B&W → saturation → tone curve → split-toning → fade). Loaded into an OpenGL ES 3.0 `sampler3D` with trilinear filtering. Degree blends `mix(original, lut(original), lutStrength)`. | Offline gen + P3 |
| 3 | **Film grain / sensor noise** | Procedural, animated value-noise in the fragment shader: hash-based luminance grain (size = `grainSize` px via UV quantization) + independent chroma noise for video eras. Grain is **luminance-weighted** (stronger in midtones, like real film) and re-seeded per frame. No texture asset needed; resolution-independent. | P3 |
| 4 | **Vignette** | Radial falloff `smoothstep(inner, outer, dist(uv, center) * aspectCorrect)`; two modes: soft natural lens falloff (wide smoothstep) vs. hard oval plate mask (narrow smoothstep, used 1900s/1910s). | P3 |
| 5 | **Halation / bloom / soft focus** | P2 produces a half-res 9-tap separable Gaussian blur. **Soft focus** = `mix(scene, blur, softFocus)` (pictorialist 1900s–1910s). **Halation** = `screen(scene, max(blur − threshold, 0) * halationTint)` with a warm red-orange tint (film-base reflection look, key for 1960s–70s). | P2 + P3 |
| 6 | **Light leaks** | Pre-generated warm gradient-blob textures (additive blend), with a slow time-driven UV drift + opacity flutter so leaks feel organic in preview; randomized variant per capture. | P3 |
| 7 | **Dust / scratches / plate defects** | Pre-generated overlay textures (specks, fibers, vertical scratch lines) screened/subtracted over the image; preview cycles between variants every ~0.7 s for a projected-film feel; capture picks one at random. | P3 |
| 8 | **Resolution & sharpness** | Down-res: P1 renders into a smaller FBO (e.g. ×0.45 for VHS) which is then upsampled with bilinear softness. Sharpness: unsharp mask `scene + (scene − blur) * sharpAmount` (positive = 2000s oversharpened, zero/negative = soft lenses). | P1 + P3 |
| 9 | **Aspect ratio & frame overlay** | Preview/capture fixed at 3:4. Frame Switch alpha-composites a per-era PNG (film gate w/ sprockets, deckled print border, VHS OSD, etc.). Preview: textured quad pass; capture: CPU `Canvas` composite at full resolution. | P4 / capture compositor |
| 10 | **Gate weave + flicker + tape flutter** *(preview only)* | Gate weave: low-frequency 2-axis sinusoid UV offset (±0.3 % UV, ~1.2 Hz with jitter). Flicker: global gain modulated by smoothed noise (±4 %). Tape flutter (VHS): per-scanline horizontal displacement bursts + chroma subcarrier shift. Disabled for stills (a still cannot "weave"); the still keeps grain/dust/scanlines so it reads as the same era. | P1 (weave) + P3 (flicker/flutter) |

**Layer ordering rationale:** geometry first (weave/down-res must happen before grading so artifacts get graded too), color science (LUT) before grain (grain sits "on the print", not under it), vignette after grain (lens/gate falloff darkens everything), physical-medium defects (dust, leaks) on top, frame last.

## 0.2 Era Spec Table (13 dial stops, 1900s → 2020s)

**Why 13 stops:** the real Eras Dial has 10 (1930s–2020s). We must add 1900s/1910s/1920s. Rather than consolidating (e.g. merging 1940s/50s), we keep **one stop per decade = 13**: each decade has a genuinely distinct dominant photographic medium (see "Real-world basis"), and a rotary dial handles 13 detents comfortably.

Research basis per era is summarized inline; the early decades are grounded in well-documented photographic history (orthochromatic emulsions, Autochrome Lumière 1907, panchromatic film c. 1920s, Kodachrome 1935, Super-8 1965, VHS 1976, consumer digicams late 1990s).

| **1900s** | Silver-gelatin dry plates & albumen prints. **Orthochromatic** emulsion: blind to red (reds render near-black, blue skies blow out). ## 0.3 Intensity model — Degree Control (0–10)

Let `d = degree / 10 ∈ [0, 1]`. The degree never fully disables an era (degree 0 is "subtle", not "off") and never exceeds the tuned maximum (degree 10 = the values in the table). Per-layer scaling curves:

| Layer | Scaling curve | Rationale |
|-------|---------------|-----------|
| LUT strength (color/tone) | `lutStrength = lerp(0.30, 1.00, d)` (linear) | Color is the era's identity; present even at 0, fully linear so the slider feels proportional. |
| Contrast trim | `lerp(0.40, 1.00, d)` applied to the era's contrast delta | Follows color. |
| Grain / noise | `lerp(0.15, 1.00, d²)` (quadratic) | Defect layers should stay nearly clean at low degrees and ramp late. |
| Vignette | `lerp(0.25, 1.00, d)` | Lens character reads as "era" early. |
| Soft focus / halation | `lerp(0.20, 1.00, d^1.5)` | Softness destroys detail; ease in. |
| Dust / scratches / leaks | `lerp(0.00, 1.00, d²)` | Pure defects: absent at degree 0. |
| Down-res / artifacts (scanlines, flutter, weave, flicker) | `lerp(0.30, 1.00, d²)` for intensity; down-res factor lerps from `mix(1.0, eraScale, d)` | Resolution loss is drastic; quadratic keeps low degrees usable. |
| Sharpness (unsharp ±) | `lerp(0.30, 1.00, d)` × era amount | Linear, mild layer. |

The `EraEngine` evaluates these curves on every parameter change and pushes a flat `EffectParams` uniform block to the renderer — no shader recompilation on dial/degree changes.

Historical grounding: **exposure** was always the photographer's call (plate exposure time → aperture/shutter → digital EV compensation), so the EV slider exists in every era and drives real CameraX exposure compensation. The first consumer **flashbulbs** ship ~1930 (before that, flash meant magnesium powder — not a camera control). Mechanical **self-timers** ("Autoknips"-style) become common in the 1930s (3 s/10 s here). Consumer **zoom** arrives with 1960s power-zoom Super-8 cameras and drives real CameraX linear zoom. Front-facing cameras are historically a 2000s invention, but the **selfie** lens stays available in every era as a deliberate usability exception; on-image **timestamps** are the signature of 1990s camcorder OSDs and 2000s digicam date stamps; the rule-of-thirds **grid** is a smartphone-app convention. A 14th stop, **2026 ("Today · as it is")**, closes the dial at the current year; the dial hard-clamps at 1900s and 2026.

The Frame Switch produces an **instant-print (polaroid-style) output**: white frame, a handwriting line for a note, and a small `era · camera · effects` credit line; frameless photos get the credit line stamped subtly on the image. Capture plays the era's shutter sound, and polaroid saves run an eject-and-develop animation.

## 0.5 Open-source survey & base decision

| Repo | What it offers | License | Verdict |
|------|----------------|---------|---------|
| `wasabeef/android-gpuimage` (`jp.co.cyberagent.android:gpuimage`) | Canonical Android OpenGL filter chain; sepia/grayscale/vignette/**2D lookup** filters | Apache-2.0 | **Not adopted.** ES 2.0-era design; its LUT filter is a 512×512 2D-packed 8-bit lookup (banding-prone), no `sampler3D`, no multi-pass blur sharing, filter-chain re-renders per filter (FBO per stage) — wasteful for a 5-layer look. Last releases are old. Studied for its shader patterns. |
| `wysaid/android-gpuimage-plus` | CameraX provider + filtered video recording | MIT (core), some NDK parts | **Not adopted** for v1 (stills app); the CameraX→GL bridge is ~100 lines we write ourselves. Re-evaluate if filtered *video* capture becomes a requirement. |
| `callebdev/Awesome-Filters` | Reference MVVM + CameraX + GPUImage app structure | MIT | **Architecture reference only** (ViewModel-owned engine state, single-activity Compose host). No code reused. |
| `xizhang/camerax-gpuimage` | CameraX `ImageAnalysis` YUV→RGB→GPUImage glue | Apache-2.0 | **Pattern studied, approach rejected**: routing frames through `ImageAnalysis` + CPU YUV conversion costs a CPU copy per frame. We instead attach CameraX `Preview` directly to a `SurfaceTexture` bound to a **GL_TEXTURE_EXTERNAL_OES** texture — zero-copy, the standard high-performance path. |
| `mikljohansson/retroboy` | Vintage-hardware emulation ideas (Game Boy camera etc.), dithering/palette techniques | MIT | **Ideas only** (its per-device "process + palette" decomposition mirrors our layer model). No code reused. |

**Decision: build the OpenGL ES 3.0 pipeline from scratch** (per the brief's explicit allowance). Justification: we need `sampler3D` trilinear `.cube` LUTs, a *shared* blur pass feeding three layers (soft focus, halation, unsharp), an external-OES zero-copy camera input, and a single über-shader composite — none of which GPUImage provides without fighting its one-filter-per-FBO chain. Going dependency-free also removes license/maintenance risk; total engine code is ~1,200 lines. The studied repos are credited in `ATTRIBUTIONS.md`.

**LUT sourcing:** every `.cube` is **generated by our own script** (`tools/generate_assets.py`) from the color-science recipes in §0.2 — no third-party LUT packs, so no licensing burden and full reproducibility (`python3 tools/generate_assets.py` regenerates all assets deterministically, seeded).
